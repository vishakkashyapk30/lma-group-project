\section{Limitations and Risks}
\label{sec:limitations}

\begin{itemize}\setlength\itemsep{0pt}
\item \textbf{One model, one run, one slice.} The test result rests on 80 blind orders, one run per system, on one hosted model (Sarvam-105B). The development runs on OpenAI and Gemini used earlier code and 2 to 50 orders per arm, so they show direction, not a ranking across model families. c1457 was selected on 30 development orders and confirmed on a 20-order holdout before the blind slice; the blind slice was opened once.
\item \textbf{RQ2 and fine-tuning not answered.} The ingestion arms on degraded, photographed and Hindi pages (S7, P5 to P8 on T2) ran only with offline stand-ins and were not scored, and the QLoRA pipeline for a 4B dossier extractor is built and unit-tested but no model was trained (no GPU time in the window). The tool-calling set T6 and the injection set T7 were not run on the hosted model.
\item \textbf{Absolute quality is still low.} c1457 wins relative comparisons, but 0.89 of its argument sentences are not entailed by the facts alone (largely legal principles from authorities, which the facts cannot entail), 86\% of the simulated prosecutor's objections stay unanswered, and the structured statutory position is empty in every brief (Section~\ref{sec:blind}). The brief is a first draft for counsel, which is how the gates treat it.
\item \textbf{Stand-in models.} The offline stand-in arms that are reported (the store knock-outs A10, the intake arms S7 and P5 to P8, the injection arm S17) carry that label in the tables and measure plumbing, not a language model. The 4B and 14B models of the design have not been run on the GPU nodes for this report; serving Qwen3-32B on the shared nodes failed and was dropped.
\item \textbf{Thin facts in T1.} The facts part is often only a caption. A single pass then answers ``no facts supplied'', while Full draws grounds from retrieved authorities not tied to the client's facts, so Full can win on recall through retrieved boilerplate.
\item \textbf{Gold is not human.} Rules plus one non-Qwen labeler that must agree; $\kappa$ is 0.60 for G1, and the agreed G1 gold leaves 81 of 250 orders without a factor. Only 37.3\% of citations resolve, and no dev order has a resolved court citation. HLDC was unavailable, so the Hindi set is native High Court orders from one court and two years.
\item \textbf{Rights Radar.} One of the seven rules is unverified. The other six match the statute store in an automatic check of each cited section's number, heading, sub-section and the conditions the rule tests (\texttt{scripts/check\_rights\_rules.py}); the check reads acts only, not the judgments a rule also relies on. A rule's verification is bound to a hash of its text and code, so a later change clears it, and an unverified rule is printed in the export as ``Not yet checked against the bare act''. T4 is generated from the same rule table, so it measures conformance, not legal accuracy.
\item \textbf{No authentication.} The gates are enforced in code, but there are no user accounts and the API token is off by default, so ``approval only from counsel'' is a property of the code path, not of an identity check.
\item \textbf{Budgets.} Spent in total: about 4.15 USD on OpenAI (locked in code again) and about INR 990 on Sarvam by 13 November, under a cap of INR 5,000 that the ledger enforces (it refuses any call past it). The free Gemini tier allows 500 requests a day per project on the flash-lite models, about 10 Full cases a day (a Full case takes about 49 requests). The full plan (about 4,500 Full case-runs) does not fit, so sample sizes are cut, not features.
\item \textbf{Known weaknesses.} Grounds are sometimes weak in substance (about ten open issues per case); the pseudonymiser still refuses one order of 250.
\end{itemize}
