\begin{abstract}
Legal-aid lawyers in India prepare bail applications from messy case files: scanned and photographed orders, Hindi and English, several documents merged in one PDF. We describe Vakeel-Sahayak.ai, a bail-preparation engine built as an agent harness rather than a single model call. Six agents (intake, dossier and rights checks, retrieval orchestration, drafting, prosecution sparring, batch triage) work over ten typed stores on four shelves. An orchestrator reads a short evidence contract for each of twelve bail factors and decides which stores to query, in which order, and when to stop. Every claim in a draft is checked against its sources, and a draft changes only where a dependency changed. Two approval gates are enforced in code, and client text passes a pseudonymisation boundary before any external model sees it. We evaluate without manual annotation: gold labels come from court text, with a rule labeler and a non-Qwen model labeler that must agree and quote a verbatim span. We compare the full system with seven simpler baselines (single pass, single store, whole-document embeddings, naive chunking, query-every-store, a learned store router, and an expert rule list) and with 18 single-switch variants taken from recent agent and RAG papers. This report describes the system and the evaluation design, and states what has run so far. On the 50-case development set (OpenAI \texttt{gpt-6-luna}, hosted, earlier code) the full system's factor recall is 0.25 on the 8 orders that have a scorable gold factor, below the baselines (0.50 to 0.88) with no gap resolved; it is clearly ahead of the single-pass and single-store baselines on objection recall (0.69 against 0.00, 20 orders) and behind the query-every-store baseline (0.93), with an unsupported-fact rate of 0.87 against 0.76 to 0.98 for the baselines and a cost of about \$0.011 per case. These numbers are preliminary: small $n$, development data only, and stand-in models in places.
\end{abstract}
